# TrueDown 1.6.4 - Reliable retries and clearer settings

This release includes the changes since `truedown-build-31`. The release workflow
assigns the `truedown-build-*` identity from its run number; the shared product
version is 1.6.4.

- Keep each HTTP download at its reserved output path across interrupted retries
  and application restarts. Failed duplicate submissions resume the same task;
  completed-file checks remain separate.
- Persist transfer intent and previous engine-result retirement in download
  database schema 7. Reject stale queued submissions and retire the previous
  result before changing partial data.
- Restart only the task's own output and control file when HTTP resume state is
  missing, invalid, or confirmed corrupt. Preserve other tasks, historical
  numbered files, and BitTorrent payload trees. File length alone no longer
  establishes completion. See `truedown/docs/download-retry-rules.md` for details.
- Organize settings into eight categories, retaining old category URLs and
  drafts. Download and network defaults save together; file groups retain their
  own save controls within File management.
- Add bounded macOS debug acceptance for native startup, close-to-hide,
  singleton windows, retained drafts, and shutdown. Release builds omit the
  fixture; no additional WebView permissions are introduced.
- Update Windows native acceptance to use File management and the independent
  group-save control after the settings reorganization.

Packaging remains Windows amd64, Linux amd64/arm64, and macOS amd64/arm64.
Publication requires every package's startup checks, native CI acceptance,
and validation of the complete asset set and Windows update hashes. macOS uses
configured Developer ID credentials or verified ad-hoc signing when absent.
